# PRD-015 — Extraction console and temperature-first dashboard

Status: APPROVED — 2026-07-28

## Summary

Split the two jobs the Dashboard graph performs today. The Dashboard keeps a
temperature-only graph and hands every extraction control to a new full-screen
extraction console, which owns profile selection, weight control, start and stop,
and the complete weighted telemetry plot. The console reads as an instrument panel
while keeping Philcoino's warm palette, typography, and card vocabulary.

This PRD supersedes two PRD-014 statements: the non-goal "Visually copying
Gaggiuino" (`docs/prds/PRD-014/PRD-014.md` line 29) and the requirement to "Use
the telemetry chart as the permanent Dashboard graph" (line 61). A dense
instrument register for the console is now an explicit goal, and the Dashboard
graph is explicitly temperature-only. Every other PRD-014 requirement, including
observation-only telemetry and the ban on synthesizing unavailable data, remains
in force.

## Goals

- Reduce the Dashboard graph to boiler temperature and target on a single band.
- Provide a full-screen extraction console with profile selection, weight control,
  start/stop, and the complete temperature, target, weight, and derived-flow plot.
- Hold the finished trace on the console after a shot ends so it can be inspected,
  and replace it when the next shot starts.
- Read as technical instrumentation using the existing palette, type scale, and
  card patterns, without a new styling dependency.
- Support portrait and mounted-landscape console layouts.
- Keep extraction mutations, profile-synchronization guards, and idempotency
  behavior unchanged while their controls move.

## Non-Goals

- Any firmware, protocol, simulator, or persistence change.
- Pressure or inlet-flow telemetry; no such sensor exists.
- Browsing or comparing historical shots on the console; that stays on the Scale
  page.
- Changing control ownership. Firmware remains authoritative and the console
  remains observation-only.
- Bundling a monospace font or introducing a styling framework.

## Context

PRD-014 made the weighted telemetry chart the permanent Dashboard graph. In use
that surface is too small to read a shot, it crowds the Dashboard alongside the
extraction control stack, and between shots it holds the finished trace instead of
returning to live temperature. The weight and flow band is also empty whenever no
weighted trace exists, which is most of the time the Dashboard is open.

Separating a calm temperature-first Dashboard from a dedicated extraction surface
resolves all three problems and gives the weighted plot the canvas it needs.

## Requirements

- Render the Dashboard graph with a single temperature band, no weight or flow
  series, no weight or flow metric tiles, and no unavailable placeholders.
- Host the console as a full-screen modal opened from the Dashboard, dismissible by
  an explicit control and by Android hardware back, without adding a navigation-rail
  page or an application route.
- Show the elapsed shot time as the console's primary readout, with dense
  temperature, target, weight, flow, phase, and pump-command readouts beside it.
- Plot temperature, target, weight, and derived flow on shared extraction-elapsed
  time with raw segments, real gaps, phase boundaries, settling, cutoff, and a
  drag cursor, and label weight and flow unavailable rather than synthesizing them
  when no trace exists.
- Drive console profile selection, weight control, and start/stop through the
  existing extraction reducers and acknowledged-mutation bridge.
- Poll scale state at the fast cadence while the console is open.
- Keep pure plot geometry, scale derivation, and readout formatting in
  localization-free modules under `apps/mobile/src/telemetry` with behavioral tests.
- Add every console string to both `en` and `pt-BR` with matching placeholders.

## Implementation Overview

1. Extract pure plot frame, plot, and readout modules with a parameterized band
   count.
2. Extract the shared telemetry surface chrome, then split the temperature-history
   and weighted-trace charts into separate components.
3. Extract the weight-control card so both the Scale page and the console can use
   it.
4. Add the console screen, its derived-state model, and its localization.
5. Reduce the Dashboard graph to one band and move the extraction controls to a
   console entry tile.
