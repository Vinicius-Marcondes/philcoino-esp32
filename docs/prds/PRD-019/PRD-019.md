# PRD-019 — Local extraction telemetry streaming

Status: Implemented — Pinned target and Human acceptance pending

## Summary

Replace high-frequency mobile scale/trace polling during extraction with one
authenticated local SSE stream. Keep the one-Hertz combined-state poll and all
REST mutations authoritative. Stream every extraction at 250 ms, retain a
bounded replay window in firmware, derive flow on the phone, and generalize
local history to Manual, timed-profile, and weighted-profile shots.

## Goals

- Reduce extraction-time HTTP request overhead without moving control or safety
  authority away from firmware.
- Deliver resumable, strictly validated temperature, heater-command, pump,
  scale, phase, and elapsed-time telemetry for every extraction.
- Preserve real gaps and continue mobile-derived beverage-flow calculation.
- Store and export every foreground/recoverable extraction until explicitly
  cleared by the user.

## Non-Goals

- VPS, cloud synchronization, remote access, command streaming, background
  execution guarantees, binary telemetry, or new dependencies.
- Replacing the one-Hertz combined-state poll or acknowledged REST mutations.
- Making Start, Stop, heater, pump, faults, or safety depend on the stream.
- Claiming heater command, pump command, derived flow, simulator behavior, or
  software tests prove physical operation or safety.

## Context

Mobile currently runs independent completion-driven state, scale, and weighted
trace sessions. During a weighted extraction this can approach one state plus
four scale plus four trace requests per second. The existing weighted trace is
resumable but excludes Manual and timed-profile shots. Expo 54 supports
streaming `expo/fetch` responses, and the pinned ESP-IDF 6.0.2 HTTP server
supports asynchronous handlers.

## Requirements

- Add authenticated `GET /api/v2/extractions/stream` with strict SSE telemetry
  pages and an optional exact boot/extraction/sequence cursor triplet.
- Retain 320 generic samples at 250 ms, page at most 16, report explicit
  continuity, stream two-second heartbeats, and keep a ten-second settling tail
  for every extraction.
- Stream selection/control mode, status/outcome, timing, phase, temperature,
  target, heater and pump commands, scale availability, nullable net weight,
  and weighted-control/terminal details.
- Allow one authenticated subscriber; reject unavailable/busy streams
  explicitly and disconnect slow clients without unbounded buffering.
- Keep capture zero-wait and bounded. Network serialization and transmission
  remain outside the workflow mutex and every control/safety deadline.
- For Manual/timed shots, capture a best-effort observational starting scale
  baseline without blocking Start. Weighted shots retain firmware-authoritative
  net weight.
- Simulator time, replay, truncation, reset, authentication, and settling stay
  deterministic.
- Mobile stops high-frequency scale/trace polling while streaming is expected,
  keeps the one-Hertz state poll, retries transient failures from the durable
  cursor, and never falls back to trace polling.
- A stream failure degrades telemetry only. REST Stop and other acknowledged
  controls remain available.
- Generalize local history and CSVs to every extraction, migrate existing
  weighted records, remove automatic pruning, and expose history from the
  extraction console.

## Implementation Overview

1. Define the strict stream/page contract and compatibility boundary.
2. Add deterministic simulator streaming and replay behavior.
3. Add the bounded firmware telemetry ring and asynchronous SSE adapter.
4. Add the mobile SSE parser/session and polling handoff.
5. Generalize storage, migration, export, history presentation, and docs.
6. Run full software/target verification and prepare separate connected review.

## Acceptance Criteria

- [x] Protocol schemas, fixtures, OpenAPI validation, and strict drift tests
  cover cursors, pages, terminal invariants, nullable scale data, and errors.
- [x] Simulator tests cover all extraction modes, reconnect, truncation/reset,
  best-effort baseline, authentication, settling, and terminal closure.
- [ ] Firmware host and target evidence covers fixed budgets, zero-wait gaps,
  async send failure, one-client enforcement, timing, heap, and stack.
- [x] Mobile tests cover fragmented SSE, commit-before-cursor, lifecycle,
  retries, polling suppression, no fallback, migration, export, and degraded
  controls.
- [x] Existing REST commands, one-Hertz state polling, weighted trace endpoint,
  firmware authority, fail-off behavior, and safety limits remain unchanged.
- [ ] Native iOS/Android and connected-target behavior receive separate Human
  review; no energized or physical-safety acceptance is inferred.
