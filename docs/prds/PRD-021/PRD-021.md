# PRD-021 — ESP32-S3 and dual-temperature-sensor migration

Status: Implemented — disconnected Human acceptance pending

Approved: 2026-08-14

## Summary

Replace the ESP32-C3 target with one ESP32-S3-WROOM-1 N16R8 target and add a
second independently calibrated MAX6675 near the steam valve. Brew remains
controlled by the boiler-base sensor, Steam becomes controlled by the new
steam-side sensor, and both readings are exposed through a coordinated API v4
mobile/firmware cutover and retained in local histories.

## Goals

- Move firmware `0.5.0` to the 44-pin ESP32-S3 N16R8 board with native USB,
  fixed task affinity, a reviewed GPIO map, 16 MB flash, and PSRAM disabled.
- Give Brew and Steam separate authoritative temperature sensors and persisted
  calibration offsets without adding automatic sensor fallback.
- Preserve fail-off heater/pump ownership, the RobotDyn 90% pump cap,
  extraction, cooldown, OTA, and independent over-temperature protection.
- Show, chart, store, and export both temperatures in the mobile app and
  deterministic simulator.

## Non-Goals

- ESP32-C3 compatibility, API v3 compatibility, or OTA migration from a C3
  image to an S3 image.
- Closed-loop pressure control, predictive-temperature deployment, automatic
  cross-sensor correction, or a sensor-disagreement fault threshold.
- Retuning Steam heater response from energized measurements.
- Flashing, energized mains testing, or electrical/thermal acceptance.

## Context

The current firmware uses one boiler-base MAX6675 for Brew and Steam and runs
on an ESP32-C3. The installed RobotDyn-compatible pump dimmer already owns
GPIO6 ZC and GPIO10 DIM with a single 90% command cap. Earlier experiments with
two thermocouple modules were unreliable when both probes touched the metal
boiler, so the selected ungrounded probes and simultaneous low-voltage reading
stability remain mandatory hardware gates.

The second probe will be mounted on the boiler body near the steam valve. Its
placement invalidates the existing Steam heat-soak compensation assumptions;
Steam will instead control directly from the calibrated steam-side reading.

## Requirements

- Target ESP-IDF 6.0.2 for ESP32-S3 only, firmware `0.5.0`, 16 MB QIO/80 MHz
  flash, native USB Serial/JTAG, and disabled PSRAM. Keep the existing OTA
  partition sizes inside the first 4 MB.
- Pin temperature acquisition, heater/workflow control, and scale work to CPU1;
  pin Wi-Fi, TCP/IP, HTTPS, mDNS, pairing, telemetry, and OTA networking to
  CPU0.
- Use Boiler MAX6675 SCK4/SO5/CS7, Steam MAX6675 SCK4/SO8/CS9, RobotDyn
  ZC6/DIM10, HX711 DT11/SCK12, and heater SSR GPIO21. Reserve native USB
  GPIO19/20 plus the selected strapping, flash/PSRAM, JTAG, UART, and LED pins.
- Serialize both MAX6675 channels through one shared-clock lock. Initialize
  both CS pins high and SCK low before sampling.
- Reject `0x0000`, open-circuit, reserved-bit, transport, and non-finite
  readings. Independently reject drops greater than 10°C from each sensor's
  last accepted sample without advancing that baseline; accept exactly 10°C.
- Brew uses only the calibrated boiler sensor and Steam uses only the calibrated
  steam sensor. An invalid active reading immediately commands heater OFF and
  three consecutive failures latch `sensor_failure`; an invalid inactive sensor
  blocks its mode without interrupting the healthy active mode.
- Never fall back or blend readings. Require a current valid destination sensor
  before a mode change, command heater OFF during transition, and reset
  readiness, duty, recovery, and timeout state.
- A raw reading above 135°C from either sensor latches `over_temperature`.
  Retain the active effective Brew 98°C and Steam 135°C limits.
- Persist independent Boiler and Steam calibration offsets. Permit one guided
  calibration session globally and retain all existing mutation, lease,
  conflict, storage-failure, and fail-off behavior.
- Remove Steam initial compensation and decay behavior and UI. Preserve only
  the configurable 1–15 minute ready timeout, migrating that value from the
  legacy NVS record.
- Replace API v3 with API v4 and require rebuilding and re-pairing the mobile
  app. Expose nullable Boiler and Steam temperatures, sensor-qualified fault
  details, independent calibration states/routes, and Steam-ready timeout.
- Add Steam temperature to extraction telemetry version 2, simulator state,
  dashboard and shot charts, local histories, SQLite migrations, and CSV
  exports. Preserve old rows with a null Steam value.
- Keep firmware, simulator, and mobile histories observational; they must not
  become heater or pump control inputs.

## Implementation Overview

1. Establish the ESP32-S3 target, fixed pins/task affinity, shared MAX6675 bus,
   and dual-sensor controller/storage policy.
2. Define API v4 first, then align firmware networking, simulator, fixtures,
   and contract tests.
3. Migrate mobile pairing, calibration, live presentation, histories, traces,
   exports, and persistence.
4. Align safety, architecture, protocol, development, wiring, and public docs;
   then complete host, sanitizer, workspace, and pinned-target verification.

## Acceptance Criteria

- [x] A clean ESP-IDF 6.0.2 ESP32-S3 build uses the fixed GPIO map, 16 MB flash,
  native USB, disabled PSRAM, and the pinned RobotDyn component without
  committed generated components.
- [x] Host tests cover both sensors' decoding, independent baselines, exact and
  excessive drops, active/inactive failure behavior, transitions, calibration,
  storage failures, over-temperature, and control races.
- [x] Brew and Steam use only their assigned calibrated sensors; no fallback or
  blending path exists, and every failure path preserves heater fail-off.
- [x] API v4, simulator, firmware captures, and strict protocol fixtures agree
  on both temperatures, sensor-qualified calibration/fault state, timeout, and
  extraction telemetry version 2.
- [x] The rebuilt mobile app requires API v4, shows both live readings, provides
  two calibration actions, and preserves nullable Steam values through history,
  trace, chart, migration, and export flows.
- [x] Existing extraction, weighted extraction, cooldown, OTA, pump cap,
  synchronization, and watchdog suites retain their safety behavior.
- [x] Normal and ASan/UBSan firmware host suites plus all affected Bun,
  typecheck, OpenAPI, simulator, and mobile tests pass.
- [x] Documentation states that prior C3/single-sensor physical acceptance does
  not apply to the S3, dual probes, new pins, native USB, or Steam sensor control.
- [ ] Disconnected low-voltage Human checks confirm exact board pin exposure,
  ungrounded probes, simultaneous stable readings, boot/reset output behavior,
  native USB recovery, sensor waveforms, zero-cross detection, dimmer 0%, and
  90% timing before any energized review.
