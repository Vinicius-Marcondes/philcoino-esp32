# PRD-020 — Simplify telemetry, profiles, and shot history

Status: Implemented — Native and connected Human acceptance pending

Approved: 2026-08-06

## Summary

Remove the ESP32 ten-minute machine-history backfill and firmware profile
persistence/synchronization. Keep one-Hertz authoritative state polling, store
received status samples locally until explicit clear, retain the short
extraction replay ring, and provide one mobile Shots surface for every Manual,
timed, weighted, stopped, failed, or incomplete extraction.

## Goals

- Reduce firmware RAM, API, and persistence work that is not used in practice.
- Keep profiles exclusively in the mobile app while firmware validates and
  latches the exact profile supplied with Start.
- Preserve received Dashboard history across lock, restart, and calendar days
  without implying that the app observes the machine while inactive.
- Record every acknowledged or reconciled extraction and present all shot modes
  in one durable history surface.

## Non-Goals

- Background polling, cloud synchronization, remote access, or multi-device
  profile synchronization.
- Making phase timing, cutoff, faults, heater, or pump safety depend on mobile
  connectivity or the telemetry stream.
- Removing scale calibration/diagnostics, extraction replay, REST Stop, or the
  one-Hertz combined-state poll.
- Backward compatibility between the old and new mobile/firmware generations.

## Context

PRD-007 added a separate 600-sample firmware history ring and paginated mobile
backfill even though foreground polls are already persisted locally. PRD-010
added bidirectional profile synchronization around a firmware-persisted profile
set. PRD-019 already streams all extraction modes at 250 ms and stores their
traces locally, but history presentation remains duplicated and a shot summary
is created only after terminal telemetry arrives.

## Requirements

- Advertise API generation `2` and require a coordinated mobile/firmware update.
- Remove `/api/v2/history` and `/api/v2/profiles` from the contract and every
  implementation.
- Profile Start carries the selected slot ID and exact name/phase durations.
  Firmware strictly validates and latches this immutable value in RAM; state and
  stream responses echo it, and idempotency includes it.
- Remove profile NVS ownership and the 600-sample machine-history ring. Ignore
  unreachable legacy profile bytes without a cleanup write. Preserve the
  independent 320-sample extraction ring and settling tail.
- Keep four app-wide SecureStore profiles and remove all remote synchronization
  UI, reads, writes, comparison, and Start gating.
- Persist each validated one-Hertz state poll. Keep all rows until confirmed
  clear, show only the current local day on Dashboard, export all rows in a
  bounded-memory flow, and render inactive periods as gaps.
- Persist a shot immediately after acknowledged Start or authoritative state
  reconciliation. Retain incomplete records when terminal telemetry cannot be
  recovered and snapshot the executed profile with the record.
- Recover streams for running and retained terminal extraction identities after
  foreground/restart. Truncation remains explicit.
- Add a fifth Shots tab containing the complete reverse-chronological history,
  trace detail, export, and confirmed clear. Remove history lists from the
  extraction console and Scale page; keep Scale for calibration, diagnostics,
  and weight defaults.
- Keep firmware authority, fail-off behavior, faults, limits, and physical
  evidence boundaries unchanged.

## Implementation Overview

1. Make the breaking OpenAPI/schema change and align the simulator.
2. Remove firmware history/profile persistence and accept inline profiles.
3. Simplify mobile profile and temperature-history ownership.
4. Add immediate/incomplete shot persistence and the dedicated Shots surface.
5. Align documentation and complete automated, native, and connected evidence.

## Acceptance Criteria

- [x] Removed history/profile routes are absent and incompatible API generations
  fail clearly during discovery or inspection.
- [x] Manual, timed, and weighted Start/replay behavior validates and echoes the
  immutable inline profile without profile NVS access.
- [x] Dashboard polling remains one-Hertz, non-overlapping, locally durable,
  gap-preserving, retained until clear, and independent from backfill.
- [x] Every acknowledged or reconciled shot is listed, including incomplete
  records, with its executed profile and available trace.
- [x] Shots is the only history list; Scale and the live console retain their
  focused responsibilities.
- [x] Protocol, simulator, mobile, firmware host/sanitizer, resource, and pinned
  ESP-IDF 6.0.2 checks pass for affected areas.
- [ ] Native layout/lifecycle and connected-target latency/timing receive Human
  review without claiming energized heater-safety acceptance.
