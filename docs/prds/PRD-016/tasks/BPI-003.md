# BPI-003 — Implement the pure Brew PI policy

Status: Done
Review Mode: Agent
Review Reason: PI arithmetic, filtering, timing, anti-windup, reset/freeze
semantics, and bounds are pure deterministic C++ policy with host-test coverage.

## Goal

Add a fixed-interval Brew-only proportional-integral controller with a
controller-owned filter, bounded finite arithmetic, and conditional
anti-windup, without connecting it to the SSR authority yet.

## Scope

- Add compile-time Brew `Kp`, `Ki`, filter constant, integral bounds, and the
  `CONFIG_PHILCOINO_BREW_PI_CONTROL` build selector.
- Implement the 500 ms PI update, bounded output, finite checks, and
  conditional anti-windup in both saturation directions.
- Define deterministic reset/freeze behavior for boot, target/mode changes,
  controller reset, fault dismissal, invalid timing/input, and inhibition.
- Expose diagnostic state required by BPI-001 without a runtime tuning path.
- Add focused pure host tests for arithmetic, irregular timing, resets, bounds,
  and arbitrary shadow outputs.

## Non-Scope

- SSR authority integration, Steam controller changes, runtime gain mutation,
  derivative control, flow compensation, persistence, mobile/API toggles, or
  physical tuning.

## Implementation Plan

1. Define compile-time constants and validate finite/range relationships.
2. Implement a single-purpose filtered PI policy with explicit update inputs
   and diagnostics.
3. Implement conditional anti-windup and deterministic reset/freeze APIs.
4. Add exhaustive host tests for nominal and adversarial numeric/timing cases.
5. Document initial gain/filter values as shadow-analysis candidates requiring
   owner approval before physical active-PI acceptance.

## Acceptance Criteria

- [x] PI updates only on valid fixed 500 ms control ticks.
- [x] Output, proportional term, integral state/contribution, and filter state
  remain finite and bounded.
- [x] Integration is rejected only when saturation and error would drive the
  output farther into the same saturation.
- [x] Reset/freeze transitions are explicit and deterministic.
- [x] No runtime API, mobile, NVS, or profile path can alter PI selection or
  constants.
- [x] Focused native and sanitizer host tests pass.

## Completion Evidence

- Added single-purpose `BrewPiController` policy with fixed 500 ms timing,
  controller-owned EMA, bounded finite arithmetic, integral limits, and
  conditional anti-windup for upper and lower saturation.
- Invalid configuration/input/timing resets and fails closed; safe inhibition
  freezes integration; target/mode/phase/fault transitions reset deterministically.
- Added default-off build selector and compile-time-only gains/filter/bounds.
- PASS — pure PI, controller transition, native, and configured sanitizer tests
  in the 10/10 firmware matrix.
- Detailed evidence: `../evidence/FIRMWARE-IMPLEMENTATION.md`.
