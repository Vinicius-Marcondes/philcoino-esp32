# BPI-006 — Migrate mobile history and CSV diagnostics

Status: Done
Review Mode: Agent
Review Reason: Networking, polling, SQLite migration, synchronization, view
models, and CSV output are strict TypeScript paths with deterministic fakes.

## Goal

Remove prediction from the mobile runtime and migrate current-day history to
retain ordinary samples while exporting only the new controller diagnostics.

## Scope

- Remove prediction opt-in polling, networking types, reducers/view models,
  debug state, and user-visible prediction values.
- Remove prediction columns from active SQLite writes and discard them during
  migration while preserving ordinary temperature/control rows.
- Synchronize the new controller diagnostics from firmware/simulator history.
- Replace CSV prediction/model columns with controller/build/gain/filter/window,
  PI/legacy request, contribution, saturation, command, phase, and mode fields.
- Preserve completion-driven polling, acknowledged state, cancellation,
  backfill gaps, device/boot/sequence identity, and current-day retention.

## Non-Scope

- Firmware control, runtime controller selection, desktop raw-data deletion,
  UI redesign unrelated to removed prediction state, or physical testing.

## Implementation Plan

1. Trace prediction fields from client parsing through polling, SQLite,
   synchronization, view models, debug data, and CSV export.
2. Remove prediction capability fallback and request query.
3. Add backward local-data migration that preserves ordinary samples and drops
   prediction values.
4. Persist/synchronize/export new controller diagnostics with command-only
   wording and nullable handling where provenance lacks diagnostics.
5. Update focused tests, then run full mobile tests, typecheck, and lint.

## Acceptance Criteria

- [x] Mobile makes no prediction request and retains no active prediction type,
  reducer, view-model, debug, or presentation state.
- [x] Existing local ordinary history survives migration while stored
  prediction values are discarded.
- [x] New history and CSV contain controller diagnostics and no forecast, model,
  feature-schema, training-hash, or hypothetical-correction columns.
- [x] Backfill, paging, gaps, cancellation, and acknowledged polling semantics
  remain intact.
- [x] Mobile tests, typecheck, and lint pass.

## Completion Evidence

- Dashboard polling now calls only queryless `/api/v2/state`; the capability
  fallback, prediction request/type/state, debug path, and hook plumbing are
  removed.
- SQLite schema v5 transactionally rebuilds v4 history, copies ordinary
  samples and source provenance, discards prediction JSON, and adds nullable
  controller configuration/diagnostics for foreground rows that lack device
  history provenance.
- Backfilled rows retain strict page configuration and per-sample diagnostics;
  CSV now exports controller build/configuration, PI/legacy requested-duty,
  contribution, saturation, anti-windup, command, phase, and operating-mode
  fields only.
- PASS — 180 mobile tests / 1,188 expectations, TypeScript typecheck, and Expo
  lint. Focused SQLite migration regression runs against an in-memory v4 table.
