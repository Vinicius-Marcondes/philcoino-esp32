# BPI-002 — Remove firmware prediction runtime and rebaseline history

Status: Done
Review Mode: Agent
Review Reason: Source removal, independent C++ codecs, fixed-size history
layout, captures, and host tests are deterministic and measurable.

## Goal

Delete prediction-only firmware runtime/configuration and replace prediction
history packing with the controller diagnostics defined by BPI-001 without
exceeding existing memory or serialization budgets.

## Scope

- Remove the prediction model/configuration, inference, feature histories,
  forecasts, fallback state, snapshot fields, codec paths, and focused tests.
- Update firmware API v2 parsing/serialization to match the breaking contract.
- Rework observational history entries, ring capacity, page serialization, and
  captures for bounded controller diagnostics.
- Preserve one-Hertz best-effort history capture and eight-sample maximum
  pages without making history authoritative.
- Record entry size, total ring RAM, JSON capacity, stack/heap implications,
  and flash deltas available before PI integration.

## Non-Scope

- PI arithmetic or control ownership, Steam changes, mobile/simulator changes,
  desktop deletion, physical validation, or new dependencies.

## Implementation Plan

1. Trace prediction-owned configuration, controller state, history fields,
   serializers, captures, and tests.
2. Delete prediction-only production and host-test code.
3. Introduce bounded firmware history diagnostics matching BPI-001.
4. Rebaseline compile-time entry/ring/page/serialization limits.
5. Update firmware captures and host validation for the matched contract.

## Acceptance Criteria

- [x] No active firmware model, forecast, hypothetical correction, prediction
  fallback, prediction query, or prediction-only feature history remains.
- [x] API v1 and queryless API v2 ordinary firmware behavior is preserved.
- [x] Firmware history emits strict bounded controller diagnostics and retains
  command-only wording for heater/pump values.
- [x] The ring remains within the existing history memory budget and the page
  remains capped at eight samples.
- [x] Firmware host tests, sanitizer suite, and contract-capture validation pass
  for this scope.

## Completion Evidence

- Deleted the prediction model/configuration/runtime source, feature-history
  ownership, live codec, enriched history packing, capture, and focused test.
- Added 40-byte fixed history entries with required controller diagnostics;
  the 600-entry `HistoryBuffer` is 24,072 bytes and an eight-entry
  `HistoryPage` is 416 bytes on the host ABI.
- PASS — native host suite 10/10.
- PASS — configured ASan/UBSan suite 10/10.
- PASS — 32 firmware response captures validate against strict schemas.
- Detailed evidence: `../evidence/FIRMWARE-IMPLEMENTATION.md`.

## Verification Strategy

- Compile and run native and sanitizer host suites.
- Validate all firmware captures against protocol schemas.
- Add compile-time size assertions and serialization-capacity boundary tests.
