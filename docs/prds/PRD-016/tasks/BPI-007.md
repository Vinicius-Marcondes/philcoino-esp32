# BPI-007 — Preserve desktop research and align documentation

Status: Done
Review Mode: Agent
Review Reason: Preservation boundaries, legacy-column ingestion defaults, and
current-state documentation can be verified by source/tests and repository
searches without subjective product judgment.

## Goal

Keep the desktop thermal-modeling implementation, raw captures, modeling runs,
PRD-012, and specifications available while clearly marking predictive firmware
integration as historical/deferred and aligning current documentation to PI.

## Scope

- Ensure desktop ingestion still accepts legacy prediction columns but ignores
  them by default and supports minimum non-predictive temperature/heater/pump
  inputs.
- Preserve raw CSV files, modeling runs, PRD-012, and both predictive/desktop
  specifications unchanged except for explicitly permitted historical/deferred
  status labeling where required by PRD-016.
- Align architecture, development, safety, tuning, protocol, README,
  side-notes, firmware README, and review references.
- Document the matched API break, controller selector, compile-time gains/filter,
  A/B evidence requirements, command-only diagnostics, and unchanged safety
  limitations.

## Non-Scope

- Deleting desktop research/data, training a model, exporting firmware
  coefficients, physical tuning, energized testing, or closing unrelated review
  findings.

## Implementation Plan

1. Characterize desktop ingestion of minimum and legacy prediction-enriched CSV.
2. Add or adjust tests so legacy columns are accepted and ignored by default.
3. Mark predictive firmware integration historical/deferred without rewriting
   historical evidence.
4. Update all current-state/public documents for PI, removed prediction surface,
   compatibility, resource, and safety boundaries.
5. Search active source/docs for stale current-runtime claims.

## Acceptance Criteria

- [x] Desktop minimum non-predictive ingestion remains supported.
- [x] Legacy CSV prediction columns are accepted but ignored by default.
- [x] Existing raw data, runs, PRD-012, specifications, and historical evidence
  remain present.
- [x] Current documentation no longer claims a live firmware/mobile prediction
  consumer and accurately describes PI A/B ownership.
- [x] No unresolved safety or review finding is weakened or hidden.
- [x] Desktop tests configured in the existing environment pass.

## Completion Evidence

- Minimum current CSV inputs are covered explicitly; legacy prediction columns
  remain readable but default features and all normal workflows use independent
  causal reconstruction. Historical logged-feature precedence remains an
  explicit reproduction-only opt-in.
- Historical header export is now standalone, so coefficient parity remains
  reproducible without restoring the deleted firmware prediction header.
- Raw CSVs, the committed modeling run/report, PRD-012, and both specifications
  remain present. Specifications and side notes are labeled
  historical/deferred without rewriting historical evidence.
- Architecture, development, safety (English/Portuguese), protocol, hardware
  tuning, simulator/firmware/desktop READMEs, contribution guides, review notes,
  and the restored review index describe the matched API break, default-off PI
  selector, command-only diagnostics, and pending target/physical gate.
- PASS — 32 configured desktop tests, including independent C++ coefficient
  parity; active-source/current-document search contains no live prediction
  consumer claim.

## Verification Strategy

- Run the existing thermal-modeling test suite without installing dependencies.
- Use scoped repository searches to prove preservation and identify stale
  current-runtime wording.
- Review documentation claims against implemented source and test evidence.
