# BPI-001 — Define the breaking controller-diagnostics contract

Status: Done
Review Mode: Agent
Review Reason: OpenAPI, strict schemas, fixtures, and drift checks provide
deterministic acceptance for the intentional matched-version contract break.

## Goal

Remove every active prediction-specific API shape and replace enriched history
with bounded controller diagnostics, while preserving API v1 and queryless API
v2 ordinary machine behavior.

## Scope

- Start in `packages/protocol/openapi.yaml`.
- Remove the prediction query, prediction response variant, prediction enums,
  forecast/model fields, and prediction fixtures.
- Define strict controller diagnostic fields for history samples, including
  selected controller, PI/legacy requested duty, controller contributions,
  saturation/anti-windup state, output-command diagnostics, phase, and mode.
- Mirror the contract in Zod exports, fixtures, and drift tests.
- Record the intentional firmware/mobile API v2 compatibility break.

## Non-Scope

- Firmware implementation, simulator behavior, mobile persistence/migration,
  desktop tooling, physical tuning, or energized testing.

## Implementation Plan

1. Characterize current API v1, queryless API v2, prediction opt-in, and history
   schemas and their accepted/rejected fixtures.
2. Remove prediction-only operations/components from OpenAPI.
3. Define the bounded controller-history diagnostic shape and limits.
4. Align Zod schemas, exported types/constants, fixtures, and contract tests.
5. Run the complete protocol validation matrix.

## Acceptance Criteria

- [x] `GET /api/v2/state?include=prediction` and
  `MachineStateWithPredictionV2` are absent.
- [x] Queryless API v2 and API v1 ordinary shapes remain unchanged.
- [x] No active protocol schema, enum, fixture, or exported type exposes
  prediction, forecast, model, or hypothetical-correction data.
- [x] History diagnostics strictly distinguish legacy-authoritative,
  shadow-PI, and PI-authoritative captures and command-only output semantics.
- [x] OpenAPI validation, protocol tests, fixture drift checks, and protocol
  typecheck pass.

## Completion Evidence

- Removed the API v2 prediction query/variant, prediction schemas/types/enums,
  and the enriched-state fixture from the authoritative OpenAPI/Zod contract.
- Added strict `ControllerConfiguration` and `ControllerDiagnostics` schemas
  with matched build identity, gains/filter/interval/window metadata, bounded
  legacy/PI terms, saturation/anti-windup state, command-only output fields,
  extraction phase, and operating mode.
- History pages now require controller configuration, require diagnostics on
  each sample, cross-check selected controller and acknowledged commands, and
  accept no more than eight matched-version samples.
- PASS — `bun run validate:openapi`.
- PASS — `bun run test`: 138 tests, 280 expectations.
- PASS — `bun run typecheck`.
- No firmware, simulator, mobile, desktop, or physical behavior was changed in
  this task.

## Verification Strategy

- Run the package OpenAPI validator, full protocol test suite, and protocol
  TypeScript typecheck.
- Add positive and rejected fixtures for controller diagnostics and explicit
  tests that removed prediction fields are rejected.
